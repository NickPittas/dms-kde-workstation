## Change 1: Obsidian Flatpak Wayland mode

Applied:

```bash
flatpak override --user --socket=wayland --env=OBSIDIAN_USE_WAYLAND=1 md.obsidian.Obsidian
```

Reason:

- Obsidian previously had X11 permission but not Wayland.
- Dolphin → Obsidian drag/drop likely failed because Obsidian was running through XWayland.
- Flathub Obsidian documents Wayland support via `--socket=wayland`; `OBSIDIAN_USE_WAYLAND=1` causes the Flatpak launcher to use Electron Wayland/Ozone flags.

Required test:

- Fully quit Obsidian.
- Relaunch Obsidian.
- Test Dolphin → Obsidian drag/drop.

## Change 2: Dolphin Meta+E launch path

Changed:

```kdl
Super+E { spawn "dolphin"; }
```

to:

```kdl
Super+E { spawn "gtk-launch" "org.kde.dolphin"; }
```

File:

```text
~/.config/niri/dms/binds.kdl
```

Reason:

- Dolphin from DMS dock had correct theme.
- Dolphin from raw niri `spawn "dolphin"` had broken alternating white rows.
- Launching via desktop entry may better match the DMS/dock launch path.

Validation:

- `niri validate` passed.
- niri config was reloaded.

Required test:

- Press `Meta+E`.
- Check Dolphin row colors/theme.

## Change 3: Nuke direct launchers

Created helper wrappers:

```text
~/.local/bin/nukex17-direct
~/.local/bin/nukestudio17-direct
~/.local/bin/hiero17-direct
```

Created desktop entries:

```text
~/.local/share/applications/NukeX-17-direct.desktop
~/.local/share/applications/NukeStudio-17-direct.desktop
~/.local/share/applications/Hiero-17-direct.desktop
```

Reason:

- Existing Nuke launchers run Nuke inside Ghostty:

```text
Exec=ghostty -e env QT_QPA_PLATFORM=xcb LC_NUMERIC=C /opt/Nuke17.0v1/Nuke17.0 --nukex
```

- For drag/drop testing, launching Nuke directly as an app may behave better than launching it as a child of a terminal.
- Nuke 17 installation only ships Qt `xcb` platform plugin, not a Qt Wayland platform plugin, so native Wayland is not currently available for Nuke.

Important limitation:

Nuke appears to be X11/XWayland-only on this installation:

```text
/opt/Nuke17.0v1/qtplugins/platforms/libqxcb.so
```

No Qt Wayland platform plugin was found under Nuke's bundled Qt plugins.

## Change 4: XWayland Dolphin helper for Nuke DnD

Created:

```text
~/.local/bin/dolphin-xwayland-for-nuke
~/.local/share/applications/org.kde.dolphin-xwayland-for-nuke.desktop
```

Launcher name:

```text
Dolphin (XWayland for Nuke DnD)
```

Reason:

- Native Wayland Dolphin → XWayland Nuke may not support drag/drop under niri/xwayland-satellite.
- If both source and target are XWayland clients, drag/drop may have a better chance.

Required test:

1. Launch `NukeX 17.0v1 (Direct)` from app launcher.
2. Launch `Dolphin (XWayland for Nuke DnD)`.
3. Try dragging file from that Dolphin into Nuke.
